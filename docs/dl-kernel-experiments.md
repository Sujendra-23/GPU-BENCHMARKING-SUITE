# DL-kernel experiments: setup and commands

Results and caveats are in the [README](../README.md#dl-kernel-experiments-second-rtx-4090-session) and
[results/dl-kernels.md](../results/dl-kernels.md) (generated by `python -m harness.dl_kernel_report`).
These commands were run on one RTX 4090 (driver 570.211.01, CUDA toolkit 12.4, PyTorch 2.4.1+cu124,
Triton 3.0.0, Python 3.11). Run only one benchmark at a time on the GPU.

## Setup

```bash
pip install ninja pytest                      # torch/triton from the CUDA 12.4 PyTorch wheel
export PATH=/usr/local/cuda-12.4/bin:$PATH TORCH_CUDA_ARCH_LIST=8.9
git clone --depth 1 --branch v3.5.1 https://github.com/NVIDIA/cutlass.git /workspace/cutlass
export CUTLASS_DIR=/workspace/cutlass         # header-only; used by kernels/cutlass/gemm_fp16.cu
```

FlashInfer and the CuTe DSL are installed in their own venvs that reuse the system torch:

```bash
python -m venv --system-site-packages venv-fi && . venv-fi/bin/activate
pip install flashinfer-python==0.2.5+cu124torch2.4 -i https://flashinfer.ai/whl/cu124/torch2.4

python -m venv --system-site-packages venv-cute && . venv-cute/bin/activate
pip install nvidia-cutlass-dsl "cuda-bindings>=12.9,<13"   # 13.x needs a CUDA 13 driver (r580+)
git clone --depth 1 --branch v4.8.0 https://github.com/NVIDIA/cutlass.git /workspace/cutlass-dsl
```

## Runs

```bash
python -m harness.attention_sweep --out results/attention/rtx4090.json     # A: attention sweep
python -m harness.gemm_bench --out results/gemm/rtx4090.json              # B: fp32 + CUTLASS fp16 GEMMs
CUTLASS_DSL_DIR=/workspace/cutlass-dsl python -m harness.cute_dsl_gemm \
    --mnkl 4096,4096,4096,1 --ab_dtype Float16 --c_dtype Float16 --acc_dtype Float32 \
    --a_major k --b_major n --c_major n --atom_layout_mnk 2,2,1             # B: CuTe DSL (venv-cute)
python -m harness.paged_decode_bench --out results/paged_decode/rtx4090.json  # C (venv-fi, for FlashInfer)
python -m harness.roofline --out results/roofline/rtx4090.json            # D: torch.profiler roofline
python -m compilers.llama_block --mode eager|default|max-autotune         # E: one process per mode
python -m harness.triton_ir_dump                                          # E: TTIR/TTGIR/LLIR/PTX
python -m harness.dl_kernel_report                                        # regenerate results/dl-kernels.md
pytest tests                                                               # GPU tests skip without NVIDIA hardware
```

## Methodology notes

- **Attention reference:** fp32 inputs through PyTorch's memory-efficient SDPA kernel (an independent implementation,
  and small enough in memory for N = 8192); tolerance 2e-3. `tests/` additionally check against the fp32 math backend.
- **Timing:** `harness/measurement.cuda_time`, CUDA events around CUDA Graph replays, median of 20 replays. Graph
  repeats per replay are 4 (N <= 2048) or 1. Compilation, allocation and autotuning happen before timing.
- **Autotuning:** `attention_tuned.py` tunes over BLOCK_M in {64, 128}, BLOCK_N in {32, 64, 128} (<= BLOCK_M),
  num_warps in {4, 8}, num_stages in {2, 3, 4}, keyed on (N, head_dim, causal). The chosen config per shape is stored
  in the JSON (`autotuned_config`).
- **L2:** the paged decode benchmark rotates through copies of the KV cache so a replay does not hit the 72 MB L2.
  The GEMM and attention benchmarks are compute-bound at these sizes and are not rotated.
- **No counters:** Nsight Compute is blocked in this container (`ERR_NVGPUCTRPERM`), so `harness/roofline.py` reports
  kernel time from `torch.profiler` and algorithmic FLOPs/bytes only.

## What each Triton stage shows (from `results/triton_ir/`)

Triton compiles a `@triton.jit` function through a chain of MLIR dialects; `.asm` on the compiled kernel keeps each stage.

| stage | file | what to look at |
|---|---|---|
| TTIR | `*.ttir` | Triton dialect: hardware-independent tile program (`tt.load`, `tt.dot`, `tt.make_range`, `tt.reduce`); no layouts yet. The tuned kernel has 4 `tt.dot` (two per K-loop, one loop for unmasked and one for masked diagonal tiles); the original has 2. |
| TTGIR | `*.ttgir` | TritonGPU dialect: every tensor gets a layout attribute (`#blocked`, `#mma`, `#shared`, `dot_op`) and `tt.dot` operands are assigned tensor-core (`mma`) and shared-memory layouts. This is where `num_warps` and `num_stages` take effect. |
| LLIR | `*.llir` | LLVM IR with NVVM intrinsics after lowering the GPU dialects. |
| PTX | `*.ptx` | NVIDIA PTX: `mma.sync` tensor-core instructions, `cp.async` global->shared copies, `ex2.approx` for `exp2`. Counts per kernel are in `results/triton_ir/summary.json`. |

This is a read of the artifacts for these two kernels, not a claim about every Triton program.
